# M10A final execution review

This review supplements the frozen section-to-control map through Section 474. Machine-readable results and the canonical controls determine the gate; a passing subtest is not overall production authorization.

## Security scope reviewed

- Authentication: supported Convex Auth Password/recovery and session invalidation retained. Direct backend sign-in/recovery inputs are bounded; unknown/archived/unassigned users fail closed. The new durable attempt table stores hashed normalized identifiers, not plaintext email/password. The 500 global, 50 sign-in/verification per identity, and five recovery requests per identity per hour limits remain unchanged after approval review rejected increasing them. No constant-time enumeration guarantee is asserted. Controlled operator onboarding is the Section 235 architecture; real first-access delivery and independent human recovery are external prerequisites.
- Authorization: central current-profile/current-role access checks remain in backend functions. New integrity queries require Owner/Admin. Migration entry points are internal only and reject shared hosted development/production. Inventory location pages admit Crew only through a currently accessible project and return minimal location fields. No browser-supplied actor can create audit identity.
- Data and provider boundaries: Marketing DTOs omit private CRM/commercial data; derived AI context remains server permission-filtered. Fixed provider adapters and encoded provider IDs are retained; no arbitrary URL-fetch or user-controlled SQL/command endpoint was added. AI navigation acceptance uses deterministic local navigation without an OpenAI call. No email acceptance was repeated.
- Public HTTP: bounded auth POST, exact same-origin checks, generic failures, authenticated server routes, nonce CSP, no-store responses, frame restrictions, missing/invalid webhook signatures, bounded payloads, and unsubscribe handling are covered by local and browser tests. Actual production HTTPS/HSTS/origins must be verified during separately authorized M10B configuration.
- Files: production source contains no active upload URL generation or file-download URL endpoint. Existing storage references are metadata. Inactive paths are not falsely labeled as tested file delivery; future upload/download activation requires its original malware/content/type/size/access/expiry gates. The isolated restore helper stores a fictional text Blob only in a private copy and is never part of hosted source.
- Privacy: no bulk customer export, destructive retention job or new provider-data transfer was added. Existing archive/correction history is retained. Scoped inspection/reconciliation artifacts contain counts and result codes; raw database exports and test identities stay ignored and restricted. Actual provider-account contracts, retention approval and privacy/legal sign-off remain external.

## Performance and concurrency

Realtor activity history now uses indexed cursor pages (30 rows); contact dates use indexed boundaries rather than collecting full histories. Activity history is ordered by creation time descending, explicitly replacing completion-time fallback ordering. Follow-up continuation can traverse sparse filtered pages; legacy page offsets above page one are rejected without a cursor. Derived Realtor sorting is capped with a clear narrow-query error, not silently truncated.

Inventory category/location selectors stream reference pages of at most 100 rows, including references beyond the original first-100 ceiling. They show loading until the reference set is complete; they are not a bulk-stock query. At very large reference counts a searchable selector remains a future usability improvement, not an unbounded backend transaction. The local regression covers 206 locations, while the existing scale suite covers 1,000 products/3,000 physical assets/1,000 ledger rows and CRM history covers 1,000 activities.

Hosted query timing is an end-to-end development-network benchmark, not a production SLA/load test. Existing M4/M5/M7 tests exercise native OCC/idempotency; the additional CRM race requires one winner for the same version. Detailed outcomes, failures and targeted reruns are recorded without combining overlapping checks into inflated totals.

## Release, operators and external work

A technical release record must link the source SHA, deployment target, test times/results, compatibility/rollback evidence and the authenticated platform/CI record. Internal platform profile audits intentionally retain a null application actor: a deploy operator is not an application user. The GitHub execution identifies its platform actor, while production privileged changes still require named human operator attribution, incident linkage and retained platform audit evidence. Do not invent a human identity for Codex.

Main was observed unprotected through GitHub's branch-protection endpoint. Required main protection/reviews/checks, protected production deployment identities/environments, MFA, responder contacts, independent monitoring destinations, legal retention approval and production backup operations must be completed during the M10B review. This task does not configure or authorize them.

Migration environment-label correction was explicitly approved by the product owner. The adapter now uses the supported development label while requiring both a loopback HTTP Convex URL and an explicit migration opt-in; shared hosted development and production remain rejected. The real isolated rehearsal passes dry-run rollback, invalid-input rollback, checkpoint/resume, exact replay, changed-source conflict and 13-record reconciliation. It found and fixed a replay defect that changed completed_at without adding records. The versioned fictional command package is a representative import adapter, not a universal legacy-history converter: source-specific production mappings, independently reviewed reconciliation and real migration approval remain mandatory. No real customer data was imported.
