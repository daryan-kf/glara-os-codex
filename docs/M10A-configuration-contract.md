# M10A configuration contract

This is preparation only. No production hostname, deployment, credential, DNS entry or provider is created by this contract. The selected real hostname is an M10B prerequisite. Run `npm run configuration:preflight -- <private-non-secret-plan.json>` against the schema in `src/lib/security/preflight.ts`. The command is offline and never contacts a provider. Its output contains fixed reason codes and credential **names**, never values. Credential custody/distinctness fields are operator attestations, not proof that a secret exists in a provider vault. An accepted disabled plan is not a production release authorization.

Approval flags do not configure providers or select a production target. Schema/UI role checks remain server enforced regardless of feature flags. Preflight currently covers plan/origin/credential metadata/feature prerequisites; actual provider custody, deployment environment verification, platform MFA and a complete hosted cross-contamination matrix remain separate readiness evidence.

CSP uses a per-request nonce and framework dynamic rendering. Production scripts have no unsafe-inline/unsafe-eval allowance; development-only framework evaluation is explicit. Inline **styles** remain allowed for Radix/layout compatibility, recorded as a limited exception. External fonts, frames, objects and arbitrary network destinations are blocked. Auth proxy accepts the supported SDK's text/plain JSON transport as well as application/json, bounds the body to 8192 bytes and requires same-origin POST. Sign-out's omitted args are normalized; unknown action/invalid body fails safely.

Explicit production frontend startup now also requires `GLARA_PRODUCTION_APPROVED=true`, a `CONVEX_DEPLOYMENT=prod:<approved-name>` selector, valid HTTPS `SITE_URL`, and matching cloud/site public URLs for that deployment. The known shared development deployment `woozy-jaguar-392` is rejected even if mislabeled as production. Missing, malformed or crossed configuration leaves authentication unconfigured and protected routes closed. This guard is preparation only: it creates no production resources and does not authorize setting the approval flag. Actual platform deployment identity remains an M10B verification duty.
