# Supply-chain and release provenance

The npm lockfile is authoritative; use `npm ci`, never an unreviewed lockfile rewrite. Pinned `@convex-dev/auth@0.0.95` has a narrowly scoped deterministic postinstall patch in `scripts/patch-convex-auth.mjs`: expected original hashes/layout and package version are checked before patching; unexpected upstream changes fail closed. The patch does not fetch executable content. Clean install must exercise this check, not rely on an already patched working tree.

Review inventory: Next/React and Convex serve production traffic; Convex Auth/Auth core implement identity; Zod validates; Svix authenticates webhook content; Radix/Tailwind/Lucide form UI. TypeScript, ESLint, Prettier, Playwright, Vitest, convex-test and tsx are development tooling. Record exact resolved versions from `npm ls --depth=0` and the lockfile SHA in the acceptance artifact. Do not auto-upgrade auth/Convex to clear audit output without compatibility and security regressions.

At this checkpoint `npm audit --json` reported no advisories in any severity category. This is a point-in-time registry result, not proof of absence of vulnerabilities. Re-run before release and after lockfile/security changes; triage exploitability and runtime exposure without suppressing unexplained high/critical findings. Proposed evidence expiry is seven days.

No GitHub Actions workflow exists in this repository. No CI permissions, branch protection or required review is claimed configured. Before M10B, a named GitHub administrator must verify protected main, required review/checks, least-privilege scoped deploy identity, protected production environments and no secrets exposed to untrusted pull requests. Any later workflow must pin third-party actions by immutable revision, use read-only token defaults and explicit restricted deployment jobs; do not use pull_request_target to run untrusted code with secrets.

Clean install/build and bundle inspection are recorded in `M10A-continuation-results.json` with exact source provenance. Production source maps are not intentionally published; verify `.next/static` contains no maps and no private environment/provider credential values before promotion. Public Convex URLs are configuration, not credentials. Runtime/browser and external environment verification remain separate. A release comprises the source commit, lockfile digest, build/check results, approved schema-change inventory and rollback compatibility review. Never equate a successful build with permission to deploy production.

Fresh install also reports upstream deprecations for transitive Lucia/Oslo packages and the pinned ESLint release. An advisory-free audit does not resolve maintenance/support risk. Review the Convex Auth dependency/support path and toolchain upgrade separately; no emergency untested upgrade or risk waiver is applied.
