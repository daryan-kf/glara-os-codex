# Production data migration preparation

Production is not created or imported during M10A. There is no approved real source dataset or user mapping. The isolated backup drill is **not** production migration acceptance. Do not import the development snapshot into production.

Inventory intended authoritative groups: approved company settings and reference catalogs; brokerages/lead sources/Realtors; properties/opportunities/quotes; projects/rooms/events/checklists; inventory products/assets/stock/reservations/movements; agreements/customers/invoices/payments/allocations/credits; legitimate communication consent/suppression/history; required audit provenance. Rebuild analytics projections from authoritative facts and reconcile. Business Owner must approve which groups actually migrate and establish source ownership.

Exclude fictional acceptance data, test identities/passwords, active sessions, refresh/recovery/invitation tokens, API keys, environment values, deployment credentials, provider OAuth material, active queue leases, automatic pending sends, old AI execution jobs, and temporary local artifacts. Historical communications may be imported only as immutable history with approved privacy scope; they must not be replayed. Provision real employees through the approved onboarding flow, not copied development credentials. Preserve retired/archived assets and financial corrections where policy requires; do not silently discard them.

Planned importer contract (implementation and rehearsal still open): a versioned source manifest with stable `(source_system, source_record_id, transform_version)` identities, content digests and a persisted source-to-target ID map; deterministic UTF-8 normalization; decimal strings converted to integer cents using existing money validation; dates retained as Vancouver business dates or UTC instants according to source precision. Validate duplicate contacts/asset codes, FK references, money totals/allocations, valid stages/statuses, prospect next action, user/role mapping and reservation overlap before write. Reject invalid rows into a restricted report with row identifiers/reason codes, not a raw payload dump.

Phases: approve/freeze source and snapshot; dry-run validation; reference/user mappings; CRM/sales; projects; inventory; commercial; approved history/audit; rebuild projections; reconciliation. Each phase records source/version/operator/target/start/end, accepted/rejected counts and checkpoint digest. Same identity+digest is a no-op; changed source digest is an explicit conflict; resume only after verifying prior checkpoints. Bounded batches are required. No unreviewed generic import endpoint is added here.

Before M10A migration acceptance, implement and rehearse this contract against a concrete fictional/sanitized representative source, including duplicate retry, interruption/resume, conflict and rejection cases. Reconcile counts, relationships, signed financial balances, Inventory identity/reservations and analytics independently before any customer access. M10B needs a separately authorized execution plan and named operator/verifier.

Rollback: before writes, abort safely; during a phase, retain the target frozen and repair by stable identity or discard a newly created isolated target. After financial/audit acceptance, use compensating changes with audit or a separately approved full restore, not blind deletion. Code rollback does not undo data. Unknown external effects require reconciliation before retries. No production importer or rollback rehearsal is claimed complete.
