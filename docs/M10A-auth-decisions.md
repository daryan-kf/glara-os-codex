# Authentication decisions and remaining gates

Keep the existing Convex Auth architecture and cryptography. The current M10A change uses supported session invalidation and a before-session callback to reject archived, absent or unassigned profiles. Do not implement custom token signing, hand-built TOTP or bypasses for a locked-out Owner.

Section 235 explicitly permits controlled operator provisioning with secure initial credential/recovery delivery. That is the selected architecture for this milestone: no public signup, no plaintext production passwords; a trusted deployment operator establishes a profile/roles with an undisclosed random password, followed by the supported recovery flow. There is no independent invitation-token product. Do not claim invitation-specific expiry or inviter revocation tests as passed. Actual delivery/origin and independent Owner proofing remain pre-production requirements.

Current corrections contain profiles before a platform role/archive change, invalidate sessions using the supported Convex Auth API, remove pending recovery codes and restore the desired profile only after verification. Concurrent/interrupted changes fail closed. Platform audit actor remains null and must be correlated with named deployment operator evidence; it is not an authenticated application actor. Owner-driven emergency revocation derives its actor from server identity.

Eight framework recovery tests cover single-use redemption, destroyed old sessions, expiry, archival, mismatch and invalid-code throttling without sending emails. The proxy sanitizes HTTP errors and enforces same-origin bounded JSON. Direct-backend issuance now produces uniform recovery responses for unknown, active and archived accounts and applies durable hashed-identity attempt windows. Twelve isolated desktop/mobile browser checks pass expired/mismatched/valid/reused codes, new-password login and logout. Codes were seeded in a private loopback-only test deployment; no mailbox/provider delivery is claimed. Production redirect/origin and actual secure delivery evidence remain open. Historical M9 email acceptance does not pass production authentication delivery.

Privileged MFA is a mandatory M10B blocker. A supported identity architecture must be selected and verified against Next.js/Convex before enablement; no unsupported claim that the current password flow implements MFA. Named platform operators must also use strong MFA and independent recovery channels. Record product-owner approval and actual account evidence; do not silently waive MFA because other hardening passes.

Trusted Owner recovery requires another independently verified accountable operator/channel outside the compromised application session, documented proofing, attributable platform changes and subsequent session/code revocation. The new self-revocation refusal does not solve Owner recovery. Restricted contact and incident-store templates require real humans and ACL review before go-live; no contact details belong in this public repository. These are tracked by IR-01, IR-03, IR-04, AUTH-MFA and AUTH-RECOVERY.
