# Canonical readiness and evidence

`M10A-readiness-controls.json` is the status source of truth. `M10A-evidence-register.json` contains sanitized references and metadata only. The generated `M10A-readiness-summary.json` must never be hand-edited. `M10A-control-map.json` maps all received sections to material controls. Historical checkpoints are retained as historical, not conflicting current status. IR-01–IR-07 retain their identifiers and original history.

Run `npm run readiness:check`; run `npm run readiness:summary` to regenerate the summary. `npm run readiness:gate` also requires an actual M10A pass and deliberately exits nonzero while blockers remain. M10B is unauthorized regardless of a machine result. Entry readiness requires named humans on all release-critical controls; a role title or Codex's engineering execution does not appoint a human. No risk acceptance has been granted.

PASS needs relevant passing evidence of all required types in an allowed environment, current code/configuration, verified timestamps, closure references, and no contradictory failed evidence. Local tests cannot satisfy hosted/production controls. Evidence source SHAs must exist and be ancestors of the reviewed HEAD. Code freshness checks compare declared source paths; evidence authors must include all dependencies, not just the test file. Time-limited evidence expires. Changes to environment/provider configuration, migration, policy or security require explicit invalidation and rerun by the verification owner even when Git cannot detect them. This checker cannot observe remote account changes automatically.

Private evidence must never be in Git: use a controlled restricted-evidence identifier. The current CLI fails closed on inaccessible private evidence; an independent safe attestation and access-verified workflow is needed before closing such a control. No secret values, mailbox content, raw backup or incident payload is accepted. Pattern scanning is defense in depth, not a proof against every form of personal data. The release secret scan remains separate.

Use `reopenControl` to set pending_verification, clear closure and append a reason; retain historical evidence. The checker rejects secret-like content, unknown statuses/types, missing metadata, invalid source/artifact references, expired/source-changed evidence, unsupported passes, unsafe Calendar deferral, duplicate IDs, unjustified N/A and P0 risk waivers. The canonical Calendar register remains authoritative. M10A PASS and M10B entry are derived, never inferred from document existence.
